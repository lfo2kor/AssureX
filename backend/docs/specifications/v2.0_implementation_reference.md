## 2. ARCHITECTURE SUMMARY

### Agent Count Evolution
- **v1.0:** 3 agents (Jira Parser, Vision Executor, Report Generator)
- **v2.0:** 4 agents (Added Feedback Agent)

### 4-Agent System

```
User Query (Ticket ID)
    ↓
┌─────────────────────────────────────────────────────────┐
│  LangGraph StateGraph Orchestrator (Blackboard Pattern) │
└─────────────────────────────────────────────────────────┘
    ↓
[State Dictionary] ← All agents read/write shared state
    ↓
1. Jira Parser Agent
   - Parses Jira_Tickets/{TICKET_ID}.txt
   - Extracts test steps
   - Outputs: parsed_steps[]
    ↓
2. Vision Executor Agent
   - Executes steps using 3-level strategy
   - L1 (Custom) → L2 (Generic) → L3 (AI Vision)
   - If failures: keeps browser open
   - Outputs: execution_results[], browser_session
    ↓
3. Feedback Agent (NEW in v2.0)
   - Triggered only if has_failures=True
   - Presents Element Picker on live browser
   - Collects corrections from tester
   - Updates selectors.json
   - Retries failed steps
   - Outputs: updated selectors, feedback_history
    ↓
4. Report Generator Agent
   - Generates HTML report
   - Outputs: report_path, overall_status
```

### Design Pattern
**LangGraph StateGraph (Blackboard Architecture)**
- Agents NEVER call each other directly
- Orchestrator controls flow: `Agent1(state) → Agent2(state) → Agent3(state)`
- All communication via shared state dictionary
- No coupling between agents

## 4. THREE-LEVEL SELECTOR STRATEGY

### Strategy Flow
```
Step Execution Attempt:

1. Level 1 (Custom Selectors) - 80% success
   ├─ Check selectors.json for exact match
   ├─ Try data-testid, id, custom attributes
   └─ Success? → Execute step
        ↓ Fail
2. Level 2 (Generic Patterns) - 15% success
   ├─ HTML5 input type matching
   ├─ Button/link text matching
   ├─ Label association
   └─ Success? → Execute step
        ↓ Fail
3. Level 3 (AI Vision Guidance) - 5% success
   ├─ Screenshot → GPT-4o vision API
   ├─ Get element coordinates
   ├─ Generate selector from coordinates
   └─ Success? → Execute step
        ↓ Fail
   FAILURE → Feedback Agent intervention
```

## 5. FEEDBACK AGENT SPECIFICATION

### When It Triggers
- **Condition:** `has_failures = True` AND `feedback_enabled = True`
- **Prerequisite:** Browser must remain open (browser_session in state)

### Workflow Steps

```
1. Failure Detection
   └─ Vision Executor detects step failures
   └─ Keeps browser_session active

2. Failure Analysis
   └─ Categorize failure type (6 categories)
   └─ Detect blocker vs cascading failures
   └─ Group related failures

3. Interactive Correction (Element Picker)
   └─ Inject JavaScript overlay on browser
   └─ Tester clicks correct element
   └─ System validates selection
   └─ Extracts all possible selectors

4. Update Configuration
   └─ Update selectors.json with new selector
   └─ Log to feedback_history.json
   └─ Learn patterns → feedback_rules.json

5. Retry Failed Steps
   └─ Re-execute with new selector
   └─ Cascade retry dependent steps
   └─ Update execution_results
```

### Failure Categories (6 Types)

1. **Selector Issues** (Most common)
   - Element not found
   - Multiple matches
   - Stale element
   - Wrong selector

2. **Element State Issues**
   - Not visible
   - Not enabled
   - Not clickable
   - Covered by overlay

3. **Timing Issues**
   - Network delay
   - Animation delay
   - Rendering delay

4. **Action Execution Issues**
   - Click failed
   - Type failed
   - Scroll failed

5. **Context Issues**
   - Wrong page/URL
   - Modal/popup blocking
   - Authentication required

6. **Verification Issues**
   - Expected text not found
   - Wrong state after action

## 6. ELEMENT PICKER SPECIFICATION

### Technology
- **Language:** JavaScript (injected into Playwright page)
- **Activation:** Programmatic via Feedback Agent
- **UI:** Visual overlay with hover highlights

### Features
```javascript
ElementPicker {
    // Visual Features
    - Hover highlights (blue border)
    - Click to select
    - Info panel shows: tagName, id, class, text

    // Selector Extraction
    - data-testid (priority 1)
    - id (priority 2)
    - name (priority 3)
    - text content matching
    - CSS selector path
    - XPath

    // Validation
    - Check uniqueness
    - Verify element is interactable
    - Test selector immediately
}
```

### User Experience
```
1. Feedback Agent: "Step 5 failed: Click 'Submit' button"
2. Element Picker activates on live browser
3. Tester sees: "Please click the correct 'Submit' button"
4. Tester hovers → element highlights
5. Tester clicks → element captured
6. System validates → "Found: button[data-testid='submit-btn']"
7. Tester confirms → System updates config
8. System retries → "Step 5: PASSED"
```

## 8. STATE DICTIONARY STRUCTURE

### Complete State Schema (All Agents)

```python
state: TypedDict = {
    # Input
    'ticket_number': str,                    # "RBPLCD-8835"

    # Config (Agent 1)
    'config': dict,                          # plcdtest_config.yaml contents
    'selectors': dict,                       # selectors.json contents

    # Parsed Steps (Agent 1)
    'parsed_steps': list[dict],              # [{"step_num": 1, "step_text": "...", ...}]

    # Execution Results (Agent 2)
    'execution_results': list[dict],         # [{"step_num": 1, "status": "PASSED", ...}]
    'has_failures': bool,                    # True if any step failed
    'browser_session': dict,                 # {page, context, browser, playwright, active}

    # Feedback (Agent 3 - NEW v2.0)
    'feedback_collected': bool,              # True if feedback was gathered
    'feedback_session': dict,                # Current feedback session data
    'retry_results': list[dict],             # Results after retry

    # Report (Agent 4)
    'overall_status': str,                   # "PASSED" | "FAILED" | "PARTIAL"
    'report_path': str,                      # "Reports/RBPLCD-8835_report.html"
    'script_path': str,                      # "Generated_Scripts/RBPLCD-8835_test.py"
    'video_path': str,                       # "Videos/RBPLCD-8835.webm"

    # Metadata
    'execution_start': str,                  # ISO timestamp
    'execution_end': str,                    # ISO timestamp
    'total_duration_seconds': float          # 42.5
}
```

## 11. CRITICAL DESIGN DECISIONS

### 11.1 Why Configuration-Based Learning?
**Decision:** Store all project-specific data in JSON files, NEVER in code
**Reason:**
- Scalability: Each project has unique selectors
- No code deployment for selector updates
- Easy backup and version control
- Non-technical users can review/edit

### 11.2 Why Keep Browser Open?
**Decision:** Browser session persists after failures
**Reason:**
- Element Picker needs live page
- Tester sees exact failure state
- Validation happens on real elements
- Faster than restarting browser

### 11.3 Why Visual Selection vs Text Entry?
**Decision:** Element Picker (visual) as primary method
**Reason:**
- Non-technical users find it intuitive
- Reduces errors (clicking is easier than typing selectors)
- Instant validation
- Captures all possible selectors automatically

### 11.4 Why Blocker Detection?
**Decision:** Categorize failures as blocker vs cascading
**Reason:**
- Step 5 failure may cause Steps 6-10 to fail
- Fixing Step 5 may resolve all subsequent failures
- Reduces tester burden (fix 1 instead of 6)
- Smarter retry strategy

### 11.5 Why LangGraph StateGraph?
**Decision:** Use orchestrator pattern, not direct agent calls
**Reason:**
- Loose coupling between agents
- Easy to add/remove agents
- State is single source of truth
- Better debugging and logging

## 13. TROUBLESHOOTING GUIDE

### Common Issues

**Issue 1: Element Picker Not Appearing**
```
Symptoms: Feedback agent runs but no overlay shows
Diagnosis:
  - Check feedback_enabled: true in config
  - Verify browser_session exists in state
  - Check JavaScript injection logs
Fix:
  - Ensure vision_executor keeps browser open on failure
  - Check browser compatibility (Chromium/Firefox/WebKit)
```

**Issue 2: Selector Update Not Persisting**
```
Symptoms: Same failure occurs after correction
Diagnosis:
  - Check selectors.json file write permissions
  - Verify JSON syntax after update
  - Check if correct project config loaded
Fix:
  - Review feedback_history.json for update logs
  - Manually verify selectors.json was modified
```

**Issue 3: Multiple Failures Overwhelming**
```
Symptoms: Too many Element Picker prompts
Diagnosis:
  - Check if blocker_detection: true in config
  - Review failure categorization in logs
Fix:
  - Enable blocker detection
  - Fix blocker first, retry cascade
```
